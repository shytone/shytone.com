怎么读、怎么 Review AI 生成的代码

AI 又快又自信，但「看起来对」不等于对。你的工作从「写代码」变成「核对意图 + 把关风险」。

读：

  • 以意图 / 规格为基准，不读「像不像人写的」
  • 分层读：契约 → 数据流 → 集成 → 健壮性
  • 专找「貌似正确的错误」：off-by-one、吞异常、幻觉 API、边界输入
  • 连测试一起读（AI 测试可能自洽但空洞）
  • 读 diff 与调用方，而非整段重读

Review：

  • 从「逐行挑错」到「意图 + 风险」清单：契约 / 边界 / 安全 / 集成 / 性能 / 一致性 / 测试是否有意义
  • 分级把关：高风险（权限、资金、数据、并发、安全）重点审
  • 让 AI 自审，但用「真值」验证，不采信其自述
  • 流程护栏：小 diff、清晰 spec、测试先行、CI / lint / 类型检查

结论：读 = 核对意图与风险；瓶颈是判断力，不是速度。
